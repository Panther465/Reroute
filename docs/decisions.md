# Decisions

Details the briefs don't settle, the simplest choice that keeps every rule, and why. Newest last. Anything that changes scope, cost, a contract or the data model is marked **Needs team sign-off**.

## Sources of truth

1. **The project brief owns behaviour and data; the UI brief owns visuals.** The two disagree on the demo: the UI brief has Tuesday 14 October 2025, the bank at 12:30, a bus mode and the university office at priority 2. The project brief has Wednesday 14 October 2026, the bank at 12:25, no buses, tempo as a mode and priority 1. We follow the project brief everywhere, including the golden test.
2. **Sample data is labelled.** Every sample place, trip, route and travel time carries `sample: true` or sits in `examples/`, and user-facing names end in "(sample)" where a person is implied.

## Planner (rule version 1.0)

3. **Cost counts only the legs still ahead.** This reproduces the brief's numbers exactly (opt-1 = 159, opt-2 = 246, metro-then-cab = 166). Costs are kept as integers scaled by 10 so fares divided by 10 never round.
4. **The 10-minute arrival buffer before a fixed task is not waiting.** The traveller leaves later instead (the brief: "leave at the latest time that still meets the buffer"). Waiting is time stuck at a place before it opens, or at a stand before the first trip.
5. **The first leg from the place of stay leaves as late as the first task allows.** For a window task that means arriving at opening time, so the traveller doesn't wait at a closed door. The earliest departure of any day is 07:00 (`day_earliest_departure`).
6. **"Higher priority" as a tie-break** compares the visit order's priorities lexicographically (must-do tasks earlier wins), then task IDs, then leg option IDs, so equal-cost plans are always chosen the same way.
7. **Exact search pruning.** Branch and bound with an admissible lower bound (each unvisited task's cheapest incoming leg, or the 120 penalty if it may be left out, plus the cheapest leg home), seeded with the insertion heuristic's cost, plus a dominance check: a partial plan at the same place with the same tasks done is dropped when another is earlier and cheaper even after charging it the time difference as waiting. Brute-force tests prove the result is still the cheapest. Eight tasks take about 0.1 s.
8. **Tasks left out.** When first planning a day, a task that can't fit is "unplaced" and named with its reason; the rest of the day is still planned. In a re-plan a task is "moved" (to the next trip day at its opening time, or 10:00) or "skipped" (priority 3 only). Fixed tasks are never left out by the planner.
9. **Option kinds.** Faster mode: the cheapest plan that keeps every task, any mode. Move task: the cheapest plan without cabs that moves at least one task ("Keep it cheap"). Skip task: the cheapest plan that skips at least one priority 3 task. Options that duplicate another are dropped; at most three, cheapest first.
10. **`timeSavedMin`** is how much earlier the day ends than it would if everything were simply shifted and nothing closed (17:30 for the 40-minute demo, so the cab saves 30 min).
11. **`extraFareInr`** is the option's remaining fares minus the active plan's remaining fares, never below zero.

## Re-plan loop

12. **A check-in waits for the worker.** Section 13's example returns options in the check-in response, while section 6 forbids planning inside a request. The API saves the check-in, enqueues the re-plan and waits up to `CHECKIN_WAIT_SECONDS` (8 s) for the worker's result. If the worker is slower it answers 202 with `result: "pending"` and a `jobId`; the outcome also arrives as a live event.
13. **Where the traveller is** comes from check-ins and the clock: the current task is the first task in the active plan that isn't done or skipped and whose leg should already have left. Location is never needed.
14. **A done check-in may shift times earlier.** Finishing early is a shift like any other: same tasks, order and modes.
15. **A skip re-plans from scratch** (trigger `skipped`) because the traveller chose to drop the task; a task edit does the same with trigger `edited`.
16. **Plans carry the legs already travelled** as `doneLegs`, so every version shows the whole day and the summary needs only the active version. `legs` holds the remaining legs, as in the API example.
17. **Undo restores task membership too.** Activating a version moves tasks to match it: a task moved by the undone version comes back to its planned day. Done check-ins are facts and never change.

## API

18. **Auth routes are exempt from idempotency.** Replaying a sign-in or refresh would hand out stored credentials. Every other POST requires `idempotencyKey`; a test walks the OpenAPI file to enforce it.
19. **Idempotency keys are scoped to the caller** (the verified token's subject, or the IP when anonymous) and to the path.
20. **Added endpoints** (documented in the OpenAPI file and Postman): `GET /v1/places` (place search for the task form), `GET /v1/trips/:id/share-links`, `DELETE /v1/trips/:id/tasks/:taskId` (only for a task without check-ins, so the record stays complete), and three demo-only routes under `/v1/trips/:id/demo/` (`clock`, `check`, `reset`) that exist only with `DEMO_LOGIN=true`. **Needs team sign-off** (the brief asks before adding endpoints).
21. **Calendar import returns draft tasks and saves nothing.** Events without a time, or whose location doesn't match a known place, come back with `placeId: null` for the traveller to fix.
22. **Window times** (`opensAt`, `closesAt`) are local times of day (`"10:00"`), not full timestamps; fixed starts are full ISO 8601 with the offset.
23. **Live events need the access token in a header**, so the web app reads the stream with `fetch`, not `EventSource`.

## Data

24. **Exactly one active plan per trip** is a partial unique index; immutability is a trigger that rejects any change except `status`, `activated_at`, and a version set once.
25. **Database roles enforce the module boundary.** `reroute_app` owns `public` and has no rights on `raasta`; `raasta_app` owns only `raasta`.
26. **Raasta routes are directional.** The two-way Koramangala–Jayanagar corridor is seeded as two routes.
27. **If Raasta is unreachable**, its routes count as unverified, so they can only be labelled extras and the plan still works with metro, walking and cabs.
28. **The travel-time snapshot ID** includes a hash of the Raasta statuses and service hours it used, so replays stay exact.

## Raasta

29. **A route serves a leg** when its boarding stand comes before its alighting stand and each is within `WALK_RADIUS_M` (800 m) of the ends. Walking is estimated at 80 m/min and the expected wait at half the frequency, rounded up.
30. **`GET /routes` returns `rideDistanceM`**, not ride minutes: the Raasta route contract has no travel time, so travel minutes come from the travel-time snapshot (and OSRM when enabled).
31. **Before its first trip** a route is still listed and the planner's service-hours rule makes the traveller wait; only "after the last trip" leaves it out (`lastTripPassed`).
32. **A stale route goes back to verification** as a waiting `freshness_check` contribution in the moderator queue. Rejecting a new route or a freshness check removes the route.
33. **Taps within 30 m of an existing stand reuse it.** Without OSRM, route paths fall back to straight lines between stands, or to the trimmed ride points.
34. **GTFS** uses `route_type` 1501 (share taxi) and one frequency-based template trip per route; the calendar runs one year from the export date, which the request handler passes in, and the feed includes `feed_info.txt`.
35. **`/readyz` answers 500 `INTERNAL`** when a dependency is down, because the brief's error list has no 503. Raasta's Redis keys live in database 1.

## Infrastructure

36. **OSRM is an optional Compose profile.** The Bengaluru demo uses the sample snapshot (`TRAVEL_TIMES_SOURCE=sample`), so `docker compose up` works without preparing a map. `--profile routing` downloads and prepares the southern India extract for car and foot.
37. **Tests run jobs inline** (`QUEUE_SYNC=true`) on in-memory Redis; the setting is refused in production.

## Frontend

38. **The existing Figma Make app is the starting point.** It was ported to the real APIs; the client-side planner was removed so there is exactly one planner.
- **One planner.** The client-side planner from the prototype is gone; the web app renders the server's plan. `src/lib/timeline.ts` turns the trip into the timeline view model and is unit-tested against the golden plan.
- **The app's clock is the server's `now`**, never the device clock, so the demo clock drives every screen.
- **Where the traveller is, on screen:** a leg counts as being ridden between its leave-by and arrival times; "Mark done" targets the current task, else the next one. "I've left" is local only.
- **Window tags read "Open till HH:MM"**: the API doesn't distinguish "open till" from "closes".
- **Offline:** the TanStack Query cache persists for 7 days, so the active plan renders after an offline reload. Check-ins made offline are queued with their idempotency keys and sent when the phone is back online; a 4xx answer drops one, a 5xx or no connection keeps it.
- **Live events are read with `fetch`** because `EventSource` can't send the access token.
- **Code splitting:** every screen except Today loads on demand; MapLibre alone is above the default chunk warning, so the limit is 1100 kB.
- **Animated elements** (UI brief motion rules, with reduced-motion versions): the sign-in hero is a 2-second, one-shot preview of the reroute choreography on the sample day; on Today, a mode-coloured marker sits on the leg being ridden at the share of the leg already travelled and moves only when the clock does.
- **Node.js 22 LTS, not 20.** The brief names Node.js 20 for work outside Docker, but Node 20 reached end of life in April 2026 and the current test toolchain (jsdom's HTTP client) needs Node 22. CI, the web image and `engines` all use 22.
- **The app's clock runs from when the server sent `now`**, not from page load, so a plan reopened offline hours later still knows the time. The trip says whether its clock is simulated (`clockSimulated`); the demo clock holds still where it was set. The trip is always confirmed with the server on load.
- **Host ports avoid local installs:** the stack publishes PostgreSQL, Redis and MongoDB on 55432, 56379 and 57017 and plain HTTP on 8080, all configurable, so it starts on machines that already run these databases.

## Hardening after the launch audit (19 October 2026)

- **Shift only uses main options.** If a leg in the active plan now relies on a Raasta route that is unverified, stale or unconfirmed (Raasta unreachable), the shift fails as "unavailable" and the traveller gets options (reason code RAASTA_UNVERIFIED). A shared auto is never kept past its last trip.
- **A reported delay is remembered** (Redis, until the end of the day) as the time the current task will end, so the 5-minute check keeps it. Undo forgets it, so the check doesn't re-apply the undone change.
- **The automatic check acts only when the traveller is behind** (more than 5 minutes past a leave-by, or a remembered delay). It never shifts while options are waiting; it replaces them when they change and drops them when they no longer apply.
- **Accepting names the option set it saw.** `optionSetId` on accept; a replaced set answers 409 `OPTIONS_CHANGED`, an option whose first departure is more than 10 minutes gone answers 409 `OPTION_EXPIRED`.
- **A finished day is left alone:** once every task is done, skipped or moved, the way home isn't re-timed and no further versions are created. The scheduler only watches trips running today in their own time zone; `trip_ended` fires once, on the last day, after its tasks are finished.
- **A delay reported on the way to a fixed task** re-times the arrival; if it misses the fixed start (less the buffer), the result carries FIXED_TASK_AT_RISK and says when the traveller will arrive.
- **Moved tasks are planned on their new day**; Undo only brings a task back on the day it was moved from.
- **One trip, one writer:** planning, accepting and Undo take a row lock on the trip, so API copies and workers can't interleave.
- **Live streams hold no database connection**; at most 4 open streams per traveller (429 beyond that).
- **Fail closed:** an unset `APP_ENV` means production, which refuses demo login and any JWT secret starting `dev-only` or `change-me` or shorter than 32 bytes (both APIs). Docker Compose sets `APP_ENV=development` for the local demo.
- **Redis is not a single point of failure:** rate limits and idempotency fail open when Redis is down (check-ins still have their database unique key); `/v1/readyz` reports the database and Redis.
- **Supported cities** are listed on the server (`backend/app/cities.py`, Bengaluru today) with a bounding box. Place search takes the city name from that list and drops results outside the box; trips can only be created for listed cities.
- **OSRM mode** caches road tables for 24 hours, adds Raasta legs through the transit adapter (ride time estimated at 250 m a minute, about 15 km/h, a sample assumption to replace with measured ride times), and falls back to the sample snapshot when OSRM can't be reached. The worker caches Raasta answers for 5 minutes.
- **Raasta freshness** runs inside the Raasta API every 6 hours (a Redis lock keeps several copies from running it at once). Raasta's idempotency now includes the method and path, like Reroute's.
- **Fonts are self-hosted** (Fontsource: Archivo with its width axis, Atkinson Hyperlegible, Noto Sans Devanagari loaded only for Devanagari text), so there is no third-party request, they work offline, and they don't block the first paint. MapLibre isn't precached by the service worker; it is cached the first time a map opens. Built files are gzipped at image build time.
- **Adding a task re-plans its day** when that day already has a plan, the same as editing or removing one, so the traveller never has to press "plan again". The response carries the re-plan's `jobId`. A batch (calendar import, the AI helper) passes `?replan=false` on all but its last task, so the day re-plans once.
- **A skipped task is not a place reached.** Only tasks checked in done count as where the traveller has been; a skipped task's leg never joins the done legs, and with nothing under way the traveller is at the last place checked in done.
- **One button, one meaning.** The primary button on Today reads "I've left" while the traveller is still at the previous stop (kept on the phone per destination, so it survives a re-plan and a reload) and "Mark done" once they are on the way or there. Marking a task done more than 10 minutes before it starts asks first. Stops on the timeline offer Mark done, Edit and Skip.
- **No task disappears silently.** Today and Plan list the day's tasks the plan leaves out, with the planner's reason in plain words, and tasks newer than the plan, with a way to update it.
- **The AI helper uses Google Gemini's free tier** (`gemini-3.5-flash-lite`, about 2 seconds) when `GEMINI_API_KEY` is set. Full Flash models think first and took about 30 seconds, too slow for a waiting traveller. Without a key, or when the free quota is used up, the pattern parser answers.
- **Rough estimates for places without travel data** (team decision, 21 October 2026, replacing "never invent travel times" for this case only). With the sample snapshot, a task at a place found by search couldn't be planned at all, so the app only worked for the five sample places. Now, for any pair involving a place the snapshot doesn't know, the travel-time adapter adds a cab (and a walk under 1.5 km) estimated from the straight-line distance: roads at 1.3 times the line, cabs at 18 km/h plus the fare table's pickup minutes, walking at 4.5 km/h, fares from the cab fare table. These are sample assumptions. Each such option and leg carries `rough: true`, and the timeline, the Next card and leg details say "Rough estimate" and to allow extra time. Gaps between places the snapshot does know stay gaps, so the golden demo day is unchanged. The estimates are part of the saved snapshot, so replays stay exact.
- **A task under way stays under way across re-plans.** A re-plan made during a task keeps that task's leg with the done legs; the next re-plan now starts from that task too (until it's checked in) instead of from the hotel, which had tried to fit the task again and failed ("the earliest arrival is 11:55").
- **Starting is one screen.** With no trip, Plan asks where you're staying, the dates (today unless changed) and, optionally, "What do you need to do?". With a description, the trip is created and the description goes straight to "Check your tasks" (each task with its matched place, a Change button, or "Where is the …?" when nothing matched); "Plan these 3" adds them and plans the day. The check step stays because a parser can misread, and nothing is planned unseen.
- **Places in descriptions and calendar events are searched like the place search** (known places, then OpenStreetMap, cached and throttled to one request a second) instead of matching only known places. Results rank the exact name first, then names that start with the text, then names that contain it, then area matches, so "Koramangala" means the neighbourhood, not the sample bank in it. The lookups run in a worker thread, off the event loop.
- **"Add to today"** (the + on Today) opens the same describe-and-check sheet; the day re-plans once and the change plays on Today.
- **The app remembers which trip you're looking at** (kept on the phone). A new trip becomes the one shown even if another trip starts later.
- **Reset the demo deletes trips the demo account started**, because the demo login is shared: the next person starts from the sample trip.
- **Every screen without the tab bar has Back, in every state** (loading, error, not found too): one shared button that goes back through the app's history, or to the screen it belongs to when there is none (a link opened cold, a reload, the installed app).
- **Your trips** lists every trip (Today, Upcoming or Past; the sample trip runs on its demo clock, so it has no such tag) and switches between them. It opens from the date line on Today, the Plan tab and Me, and starts a new trip.
- **Tomorrow is always visible on a multi-day trip:** Today lists the next day's open tasks with their known times, and notes that Reroute plans them in the morning. The UI brief has a moved task travel into "a new Tomorrow group"; the group now exists beforehand and the moved task still travels into it.
- **"See why"** sits next to the status pill after a reroute, and the pill has a chevron, so the explanation is one visible tap away.
- **Raasta starts from your day:** a "Your next leg" card searches shared autos for the leg you're about to take, and the intro says why verified routes matter to your plan.
- **The map follows the roads and the traveller.** Legs are drawn along roads (`GET /v1/road-path`: OSRM route geometry, cached 30 days, throttled to one request a second, only for places inside a covered city, a straight line when OSRM can't answer). The map fits the active leg whenever its box resizes, so it no longer opens zoomed out. With location on, a blue dot shows the traveller with its accuracy, "Follow me" keeps the map on them, and the part of the leg behind them is greyed. Phones get a mini map of the current leg in the Next card. The team chose the free OpenStreetMap map over Google Maps: no API key or billing account, and the same features.
- **Location stays on the phone.** Tracking starts with "I've left" (or Me → Location) and runs only while the app is open. It drives "13 km to go, about 36 min" on the Next card, "Almost there" within 800 m and "You've arrived" within 120 m.
- **Alerts** at the moments that matter: 5 minutes before leaving, time to leave, a task ending in 5 minutes, nearly there, arrived. Each plays a chime, buzzes, is read aloud by Roo and goes out as a phone notification when Reroute is in the background, as chosen in Me, and always shows as a toast and is announced to screen readers, so no alert relies on sound. Each alert fires once.
- **Roo rides the timeline.** On Today, Roo sits on the Now line and moves with it. Tapping it opens a menu: Add a task, Mark the current task done (once it has started), Edit it, Need more time. Roo's own messages are status messages that never take focus, and they wait while a sheet is open. Its button stays still while the artwork moves, so it's a steady target.
- **Simulate the ride** (demo only) moves the dot along the leg's road in about 40 seconds, to show tracking and the arrival alert without leaving the desk.
- **Roo speaks with natural voices** (Microsoft Edge's neural voices, through `GET /v1/speech`, the edge-tts library): six voices (Indian English, Hindi-accented, British, American), slow, normal or fast. Signed-in only, 300 characters at most, listed voices only, each clip cached 7 days; when the service can't answer (502) or the phone is offline, the phone's own voice reads the alert. `TTS_ENABLED=false` turns it off.
- **Alert sounds are the traveller's:** in Me they turn the chime and Roo's voice on or off separately, pick a chime (Bell, Soft, Wood, Beep), set the volume (a sample plays at the new level), and pick Roo's voice and speed with "Hear Roo". The chime plays first, then the voice, so they never overlap.
- **A livelier map:** OpenFreeMap's colourful "liberty" style by day (the dark style by night, with 3D buildings added), stops as emoji pins with their names (done stops fade, the next one pulses), a glow and a moving flow along the active leg, a heading arrow on the live dot, and a tilted 3D view with an arrival card while following. The flow and pulses stop with reduced motion.
- **Every leg has its own map** on phones: "Map" under a leg on the timeline opens a compact road map of just that leg (pins, flow, live dot), with a link to full directions. One opens at a time, because phones allow only a few live maps; desktop shows the chosen leg on the big map instead.
- **A task that can't fit says why in plain terms, and offers the fix.** When fixed times inside a task's opening hours block it, the reason names them ("needs 2 h 30 min between 10:00 and 16:00, and your fixed times at 10:00 and 13:30 leave no gap that long"). On a multi-day trip the card offers "Move to Thursday": `PATCH …/tasks/:id` now takes `day` (a fixed time keeps its clock time), and today re-plans without it.
- **"I've left" remembers when it was said**, and clears itself when the trip clock goes back before then (a demo reset) or the day changes, judged only against a freshly fetched trip.
- **The Plan tab reads like a schedule:** tasks grouped by day (Today marked), ordered by planned time, each with its icon, its planned time and any problem; done and skipped tasks fold away.
- **Simulated bookings (class-project demo).** The brief leaves real booking and payments out, so Reroute simulates them, labelled "Demo booking: nothing real is booked and nothing is charged" on every screen. Train tasks (a train or station in the name or place) get "Book train ticket", and Roo offers it on Today: where to, four sample trains leaving around the task's time (classes, fares, Available/RAC/Waiting list), passengers, a demo payment, then a ticket with a PNR, coach and berth. Every upcoming leg gets "Book a cab": Uber, Ola and Rapido options (bike, auto, mini, sedan) priced from the leg, then a driver with plate, rating and OTP. Trains and cab options are generated deterministically on the server, and a booking is checked against them, so the app can't set its own fare. Bookings live in the `bookings` table (migration 0002), can be cancelled with a demo refund, and a demo reset clears them. Endpoints: `GET /v1/trips/:id/bookings`, `GET …/train-options`, `GET …/cab-options`, `POST …/bookings`, `POST …/bookings/:id/cancel`.

## Redesign and core fixes (22 October 2026)

A workspace review found the app had drifted from its own UI brief (emoji as icons, floating controls over the day, chips that changed colour by screen) and had a set of defects in the planner, Raasta and operations. The direction chosen with the team lead: keep Reroute's identity and rebuild the design system underneath, using Emil Kowalski's design-engineering rules, Impeccable's quality floor for app screens and Taste's app-screen rules where the brief is silent.

### Web app

- **One icon set, no emoji.** Stops, map pins and leg facts use lucide icons (`lib/stopIcon.tsx` guesses a stop's icon from its title, as the emoji map did). Map pins render the same icon into the marker through a React portal.
- **One chip vocabulary** (`components/ui/Tag.tsx`): Fixed is the ink tag, opening hours the green outline, Must do grey and "If there is time" sunken, on every screen; verified and unverified routes and rough estimates have their own tags with icons.
- **Timeline legs are rows, not cards** (UI brief 6.3). The next leg carries its Map and Book a cab actions; every other leg's map and cab are in its leg details, which now offer "Book a cab" too.
- **Nothing floats over the day.** Roo lives on Today's Now line only; "Hide Roo" turns it off and Me turns it back on (a saved preference). The Simulate button became a demo bar: the demo time and "Simulate" at the top of the page on phones and in the top bar on desktop. Roo no longer loops (no bobbing, swaying or confetti); it moves when it has something to say.
- **Type and motion:** titles use Archivo at 87.5% width with no letter spacing (75% made words run together); times stay at 75%. Motion uses stronger curves (ease-out `0.23, 1, 0.32, 1`, in-out `0.77, 0, 0.175, 1`, drawer `0.32, 0.72, 0, 1`), exits are faster than entrances and never ease in, and nothing appears from `scale(0)`.
- **The Next card** loses its coloured side rail and corner badge (1 px border, as the brief says); "Leave now" keeps its yellow time.
- **Browser surfaces carry the palette** (caret, accent, selection, scrollbars, MapLibre's controls in dark mode), and every control is at least 48 px.
- **Maps never take a screen down:** every map loads through `LazyMap`, which shows "The map needs a connection" offline or when MapLibre isn't cached yet, and tries again once back online.
- **Idempotency keys per attempt** (`lib/submitKey.ts`): a request keeps its key for a retry the server didn't answer, and gets a new one after a 4xx the server kept, so a corrected booking, trip, route or fare report isn't refused as a reused key. A refused cab booking refetches the cab options.
- **The offline queue** sends one flush at a time, keeps check-ins that were rate limited (429) or still being processed (409 `IN_PROGRESS`), and drops only answers the server kept. **Needs team sign-off:** the APIs report an in-flight duplicate as `IN_PROGRESS` instead of `CONFLICT`.
- **Requests time out after 20 seconds** (streams and downloads don't); a timeout behaves like a dropped connection, so a check-in queues. **The live stream reconnects** after 45 seconds without a byte (the server pings every 15).
- **When a session ends** (sign-out or a refused refresh), location tracking stops and the trip saved on the phone is cleared; check-ins waiting to sync stay for the traveller's return.
- **Alerts sound one at a time:** chime then voice, after any alert still sounding, so "leave soon" and "task ending" in the same minute never overlap. The toast announces itself to screen readers, so alerts aren't announced twice. The check-in Undo follows the toast's own timer, which waits while the toast is hovered or focused.
- **A reroute plays once:** the change clears after its choreography, so returning to Today doesn't replay it.
- **New server features in the app:** a plan the scheduler makes in the morning (`plan_updated` with trigger `morning`) raises "Your day is planned"; booking actions show only when `GET /v1/me` reports `features.bookings`; a delay check-in's `optionSetId` is used to accept without refetching; an "Already there" leg (no segments) reads "Same place, no travel" with no line, map or cab.

### Reroute API and planner

- **Already there legs.** The planner adds a 0-minute, ₹0 walk from a place to itself (option `__stay__:<placeId>`, no segments) when the travel data has none, so a checkout at the hotel, two tasks at one place and a last task skipped at the hotel all plan. The lower bound counts it only where it can be taken, so the exact search stays exact. **Needs team sign-off** (contract: legs with empty segments).
- **Unplaced tasks** stay out of re-plans of that day and are carried, with their reason, into every new version; a fresh plan (new, edit, skip, morning) tries them again. Shift-only, the end of the day and `trip_ended` work again with an unplaced task.
- **A task moved to the next day becomes "planned" there** once that day's plan includes it; the first day's summary still reports it as moved. **Needs team sign-off** (data model: task state).
- **Morning planning.** From 06:00 local time (`MORNING_PLAN_FROM_MIN`) the scheduler plans a trip day that has open tasks and no plan, from the place of stay, once per trip day (retried after 30 minutes), and only for trips the traveller planned before. Trigger `morning` (migration 0003), an automatic log entry and a notifying `plan_updated`. **Needs team sign-off** (contract and migration).
- **Option sets stay put:** the 5-minute check keeps a waiting set whose choices are unchanged (a hash of kinds, order, leave-bys, moved and skipped tasks, fares, time saved and reason codes), and check-ins return `optionSetId`. **Needs team sign-off** (contract).
- **The trip lock** is taken after travel times are fetched, as `FOR NO KEY UPDATE` with a 5-second `lock_timeout`; a timeout answers 409 `BUSY`. **Needs team sign-off** (new error code).
- **A skip that leaves no feasible day** answers 200 `no_feasible_plan` with the blocked task (it was 409, though the skip was saved). **Needs team sign-off** (contract).
- **Duplicate requests still in flight** answer 409 `IN_PROGRESS` in both APIs; `CONFLICT` stays for real conflicts. **Needs team sign-off** (new error code).
- **Raasta from Reroute:** calls carry `X-Service-Token` (`RAASTA_SERVICE_TOKEN`, a real value required in production); on 429, 5xx or no answer Reroute uses the last good answer (24 hours) and honours `Retry-After`; only a 404 makes a route unverified. **Needs team sign-off** (contract between the modules).
- **Tokens** stay HS256 with the shared secret but must carry `exp`, `iat`, `sub`, `iss` and `aud`. A per-service key pair is a follow-up.
- **Rate limits:** sign-in keeps 10 a minute per IP; refresh and sign-out get their own per-IP bucket (`SESSION_RATE_LIMIT_PER_MINUTE`, 60).
- **Simulated bookings answer 404 without `DEMO_LOGIN`,** and the user carries `features {bookings, aiHelper, voices}`. **Needs team sign-off** (contract).
- **Input checks:** `/summary?day` must be a date within the trip (422); an AI fixed time must be a real HH:MM or it is dropped; list cursors are validated (400).
- **Logs** drop query strings and mask share tokens (NGINX and the API); uvicorn's access log is off.
- **NGINX:** media may come from `blob:` (Roo's voices); the Swagger pages get their own content policy; the live stream keeps the security headers.
- **Compose** listens on 127.0.0.1 unless `BIND_ADDR` is set, and the AI helper is off by default (brief section 11). `docker-compose.prod.yml` runs production with required secrets and without the demo seed.
- **OSRM** maps are downloaded by a resumable curl service, and each profile is marked ready only once fully prepared.
- **Demo reset** forgets the trip's Redis state (reported delays, alert throttle, trip ended, check lock, morning plans).
- **Wording:** a fixed task at risk says how early or late the arrival is against its start; finishing early says the next stop moves N minutes earlier.

### Raasta

- **Ride privacy:** a recorded ride keeps only the points more than 200 m in a straight line from both its first and its last point (it was 200 m along the path, which GPS jitter at a stand used up). **Needs team sign-off** (rule change).
- **Rides are stored only once valid:** the trimmed ride is written to MongoDB just before the commit; a MongoDB failure answers 503 `UNAVAILABLE` and saves nothing, and rejecting a recorded ride deletes its points. **Needs team sign-off** (new error code).
- **Linear stop suggestion** on rides thinned to at most 2,000 points, and at most 20 suggested stands; a crafted ride can no longer hold the API for minutes.
- **Verification within the brief:** a moderator can't approve their own contribution (403); a second contributor verifies a new route only with their own evidence (a recorded ride or a tapped location) and only if they haven't contributed to it before; a stale route needs a moderator or two different riders since it went stale. **Needs team sign-off** (rule changes).
- **Confirmations:** one per rider per route per local day; `confirmationsCount` counts different riders. **Needs team sign-off** (contract).
- **Stands** appear in `GET /stands` only when they are sample data or on a verified or stale route. **Needs team sign-off** (contract).
- **Cities:** contributions must name a served city (`raasta/app/cities.py`, as Reroute's) with every point inside it; GTFS exists only for served cities. **Needs team sign-off** (contract).
- **Service callers:** `X-Service-Token` uses its own rate-limit bucket (`SERVICE_RATE_LIMIT_PER_MINUTE`, 3,000) and can't write.
- **Errors and logs:** unhandled exceptions answer with the 500 body, trace ID and `X-Request-ID`; malformed cursors are 400; `idempotency_key` is honoured like `idempotencyKey`; one masked log line per request.


## Showcase additions (22 October 2026)

- **"Why this plan?"** The worker that makes a plan also works out its reasons, in the same job: the same day planned cab-and-walk only and with no cab, every way Reroute knew for each leg with its planner cost, and whether the order search was exact. It is stored with the plan (`plans.insight`, nullable JSONB, migration `0004_plan_insight`) and read by `GET /v1/trips/{id}/plans/{version}/insight`, so nothing is planned inside the request (brief rule). A plan saved before this answers 404 with "Plan the day again". If the reasons can't be worked out the plan is still saved, without them. **Needs team sign-off** (new endpoint and column).
- **A landing page at `/signin`.** Visitors see what Reroute does before signing in: a live demo of the golden day (run the meeting 15 or 40 minutes late and the day re-routes; the times are the planner's own answers from the golden test), real screenshots of the app, and the demo account button. The screenshots stay out of the offline cache.
- **Talk to Roo.** In the chat with Roo, the microphone button listens where the browser can turn speech into text (Chrome, Edge, Safari), and Roo answers out loud. One sentence, read with plain patterns, no AI: "20 minutes late" opens Running late with 20 filled in (still one tap to confirm), "done" marks the stop done with the usual Undo (and the usual check when it hasn't started), "I've left" starts the ride, "what's next" says the next departure, "add" opens the task form. Roo answers on screen and out loud. NGINX's `Permissions-Policy` now allows the microphone for Reroute's own pages. The browser's speech service hears the sentence; Reroute never receives the recording (`docs/data-and-privacy.md`).
- **Roo is a companion you can talk to.** Tapping Roo on Today, or **Ask Roo** in the desktop top bar, opens a chat (a sheet on a phone; a panel beside the page on a desktop, so the timeline re-routes in view). Roo understands common requests on the phone with plain patterns (`frontend/src/lib/roo/brain.ts`): running late, done, I've left, what's next, skip or move a task, change its start time or length, plan the day again, undo, light or dark mode, voice on or off. Every change to the day is a card the traveller confirms, then runs through the same actions as the buttons (Undo still works) and Roo reports where the day stands. With the AI helper on, a message the phone can't place goes to `POST /v1/trips/{id}/roo`: Gemini sees the day in words and proposes at most one action, which the server checks against the trip (a real task, a real time, a length in range) before the app shows it. **Needs team sign-off** (new endpoint). The chat history stays in the browser for the session.
- **Roo feels alive.** It breathes (a slow CSS transform on the compositor), blinks, glances about when left alone, follows the pointer, and has faces for thinking, listening and talking (its mouth moves while it speaks). This is a second loop beside the Now pulse, against the UI brief's "nothing loops" rule, at the product owner's request; reduced motion stops all of it.

## Accounts, a wallet, flights, and Roo as a companion (22 October 2026)

- **Accounts with an email and a password**, beside Google: `POST /v1/auth/signup` and `/v1/auth/login`. Passwords are kept only as a salted scrypt hash (Python's standard library: N 2^14, r 8, p 1), one password account per email in any case (a partial unique index), and a wrong email and a wrong password get the same 401, in the same time. Both paths share the 10-a-minute sign-in limit. **Needs team sign-off** (new endpoints and column).
- **A wallet of simulated money** (`wallet_entries`, migration `0005_accounts_wallet`; `GET /v1/wallet`, `POST /v1/wallet/topups`). The balance is the sum of the entries. New accounts get ₹2,000, the demo accounts ₹5,000 (the demo reset restores it). Like bookings it exists only with `DEMO_LOGIN`. **Needs team sign-off** (new table and endpoints).
- **Bookings are paid from the wallet** in the same transaction as the booking: too little money is 409 `INSUFFICIENT_FUNDS` with the shortfall, and nothing is booked. Cancelling refunds, less ₹60 a passenger for trains and ₹500 for flights. **Needs team sign-off** (new error code).
- **Simulated flights** from an invented airline, SkyHop (`GET /v1/airports`, `GET /v1/trips/{id}/flight-options`, booking `kind: flight`), priced from the great-circle distance between ten Indian airports.
- **Invented partners only.** The simulated cabs said Uber, Ola and Rapido; they are now RideNow (cars), AutoGo (autos) and ZipBike (bikes), trains are booked through RailGo, and flights through SkyHop, so no fake booking carries a real company's name. **Needs team sign-off** (the cab `provider` values in the contract change).
- **Connected services** (Me) are switches kept on the phone: connecting a partner is a pretend sign-in, and a booking sheet asks for the partner before booking. The demo account has them all; a new account none.
- **Roo meets new accounts** on `/welcome` (any account with no trip goes there from Today): a full-screen, animated Roo introduces itself and sets the trip up by chatting (lib/roo/flows.ts, a tested reducer; the app does the work: create the trip, add the tasks, plan). "Set it up myself" goes to the form on Plan.
- **Roo holds conversations.** "I want to replan" asks what changed and follows up; "make an entirely new plan" asks whether to adjust this plan or start a new trip first. Every change still ends in a card the traveller confirms. Roo's lines type out word by word, and Roo reads them aloud by default (a mute button in the chat; a switch in Me).
- **Planner rule: a first plan never drops a task for being dear to reach.** Leaving a task out cost a flat 120 minutes, less than a long rough-estimate cab ride, so a real account's first plan could leave out every task it could reach only by cab. On a first plan (leaving out allowed, moving and skipping not) leaving a task out now costs more than any day; a task is unplaced only when it can't fit. Late re-plans still weigh a dear ride against moving a task. The golden day is unchanged. **Needs team sign-off** (planner rule).
- **The demo account is off unless switched on.** `DEMO_LOGIN` now defaults to off in Compose, so a fresh stack offers Create account, Sign in and Google only; `GET /v1/auth/options` tells the home page whether to show the (now small) Use the demo account. The simulated bookings, wallet and partners move to their own switch, `SIMULATED_SERVICES` (on by default, off in `docker-compose.prod.yml`), so real accounts keep them without the demo. CI turns `DEMO_LOGIN` on for Postman and the browser tests, which drive the demo day. **Needs team sign-off** (a default change and a new endpoint).
